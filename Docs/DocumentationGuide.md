# Documentation guide

Start from the project's purpose and the real maintenance task. Select topics only when they preserve information that would otherwise require investigation; do not fill a generic document tree.

Keep reusable lessons in Docs, current context and experience in Walkthrough, and disposable probes in NewTemp. A lesson must explain its conditions, observed result, evidence and what change would invalidate it. Do not label a source inspection as a runtime test. Do not invent user approval, historical events or permanent rules from one-time instructions.

Keep each explanation in one place and link to it from the closest index. Explain what each linked document is for. Preserve meaningful contract details while avoiding raw output, file inventories and general tutorials. Choose the structure needed by the actual subject rather than giving every document the same headings.

Update obsolete information as part of the related code change. Add new knowledge only when there is a new reusable result. Check new links and whether a maintainer can perform the real task without repeating the investigation. No separate tool or dependency installation is authorized by documentation work alone.
