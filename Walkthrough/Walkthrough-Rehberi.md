# Walkthrough handoff

Read this guide completely on first adoption; do not reread unchanged content already known in the session. Minimize reading and writing tokens only within this workflow. Other work follows its own requirements.

Select records by filename before opening contents. Read the newest project context and newest relevant accumulation record, then relevant records written after that accumulation. If an older subject is needed, search record names and prefer the newest applicable experience. Stop once the task's context is understood; do not scan Git or chat history to manufacture a narrative.

Create a new file when an observed result or changed direction affects future work, and before leaving an unfinished task. Name it `yyyy.MM.dd HH.mm.ss - Descriptive subject.md` using the actual local writing time. The subject must identify the result or changed understanding. Keep the current project context, the observation that changed the approach and the consequence for continuation in a few paragraphs. Link detailed reusable knowledge in Docs rather than repeating it. Do not include raw logs, inventories, apologies or unobserved history.

Do not rewrite older records as the normal update mechanism. Correct invalidated conclusions explicitly in a new record; a known old record may receive a short timestamped correction. When reading many records becomes necessary, create a new dated accumulation record naming its scope and last covered record; preserve the important changes in understanding. Do not create one just because time passed.

Check the new record's links, filename and evidence. New records do not require a central index update. If no meaningful new information exists, add no record.
